# 投稿機能定義書

**バージョン:** 1.5
**作成日:** 2026-06-27
**更新日:** 2026-07-30

> ✅ **2026-07-30 更新（6-B着手前ゲート GATE-04対応）：** 編集時の楽観ロックを`updatedAt`ベースから専用の`version`列ベースへ変更（3.4節・4節参照）。`updatedAt`はいいね・コメント等の非正規化カウンタ更新でも進むため、無関係な操作だけで本人の編集保存が誤って409になる不具合があった。`version`は投稿本体の`updatePost`呼び出し時のみ進む。

---

## 1. 機能概要

旅行スポットの記録を投稿する機能。スポット名・感想テキスト・写真（複数枚、最大20枚）・エリア・訪問日・カテゴリ・評価を 1 件の投稿として管理する。
写真は AWS S3 に保存し（オブジェクトキー: `uploads/{ownerUserId}/{uuid}.{ext}`）、URL を DB（PostImage テーブル）に保存する（実装計画書 Phase 6-A で対応済み）。投稿削除・画像差し替え時は不要になったS3オブジェクトを削除する。
投稿は本人のみ編集・削除できる。編集は`version`による楽観ロックの対象で、他のリクエストが先に更新していた場合は409エラーになる（3.4節参照）。

---

## 2. ユーザーストーリー

| ID | ストーリー |
|----|-----------|
| US-01 | ユーザーとして、訪れた旅行スポットを写真・感想・エリア・訪問日・カテゴリ・評価とともに投稿したい |
| US-02 | ユーザーとして、投稿に複数枚の写真を添付したい |
| US-03 | ユーザーとして、自分の投稿を後から編集したい |
| US-04 | ユーザーとして、自分の投稿を削除したい |
| US-05 | ユーザーとして、投稿の詳細（写真・感想・コメント）を確認したい |
| US-06 | ユーザーとして、自分の投稿をどの画面からでも編集・削除したい |
| US-07 | ユーザーとして、旅行プランと投稿をリンクさせて費用を記録したい |

## 3. 機能詳細

### 3.1 投稿作成

- 入力項目：
  - スポット名（title）・感想（body）
  - エリア（location）：47都道府県からドロップダウンで選択（**必須**）。旅行レポートの集計に使用
  - カテゴリ（category）：観光 / グルメ / 宿・ホテル / 自然 / アクティビティ / 歴史・文化 / その他
  - 評価（rating）：星1〜5
  - 訪問日（visitedAt）：DATE 型。**必須入力**
  - 費用内訳（costBreakdown）：`[{ label: string, amount: number }]` の配列。自分のみ表示。合計を `cost` フィールドに保存
  - 写真（複数枚）
  - 緯度/経度（任意）：`LocationPicker` で地図クリックによりピン設置。詳細は地図機能定義書を参照
- 処理フロー：
  1. フロントエンドで写真を選択（クリックまたはドラッグ&ドロップ、複数枚可）
  2. `POST /api/upload/post` で各写真をS3にアップロード（キー: `uploads/{ownerUserId}/{uuid}.{ext}`）→ URL を取得
  3. `POST /api/posts` で投稿データ + 画像URL配列を送信（レスポンスは投稿オブジェクト全体）
  4. PostImage テーブルに displayOrder 順で保存
  5. 新規作成成功時（編集は対象外）、フロントエンドはレスポンスをそのままホーム画面の「新着」キャッシュ先頭に追加（`setQueryData`）した上で `/?highlighted=<投稿id>` へ遷移し、該当投稿までスクロール＆一時ハイライトする（詳細は画面設計書 S-03・S-05、シーケンス図「5. 投稿作成」を参照）
- 写真の制約：
  - 対応フォーマット：JPEG / PNG / WebP / GIF
  - 1枚あたり最大サイズ：10MB
  - 最大枚数：20枚（`imageUrls`のAPIバリデーション上限。上限に達すると追加アップロードはクライアント側でブロックされる）
- 画像URLの書き込み制約：`imageUrls`に設定できるのは自分がアップロードしたS3オブジェクト（`uploads/{自分のuserId}/...`）のみ。投稿編集時は、それに加えて更新前からその投稿に設定済みだったURLも許可される（他人のS3オブジェクトや任意の外部URLを設定することはできない）

### 3.2 投稿一覧表示（フィード）

- フォロー中ユーザー＋自分の投稿を新着順に表示する（`GET /api/posts`）
- 各投稿カードに表示する情報：
  - 投稿者のアバター・ニックネーム
  - スポット名（title）
  - 先頭の写真（PostImage の displayOrder=0）
  - エリア（location）・カテゴリ・評価（星）・訪問日
  - いいね数・コメント数
  - 投稿日時
- N+1 対策：`findMany` 時に `author`・`images`・`_count（likes/comments）` を `include` で一括取得する

### 3.3 投稿詳細表示

- 全写真をスライダー形式で表示する（order 順）
- 感想テキスト全文を表示する
- エリア・カテゴリ・評価・訪問日・投稿日時を表示する
- いいね・コメント・行きたい・訪問済みの各ボタンを表示する
- 地図：緯度/経度が設定されている場合のみ Leaflet.js で表示
- 関連スポット：同エリアの他投稿をいいね数降順で最大4件表示（地図とコメントの間）

### 3.4 投稿編集

- 本人のみアクセス可能（他ユーザーが `/posts/[id]/edit` にアクセスした場合は 403）
- 既存の値をフォームにプリセットした状態で表示する
- 写真の追加・削除・並び替えが可能。並び替えは `dnd-kit` によるドラッグ&ドロップで実装（2026-07-12追加。新規投稿作成画面でも同様に利用可能）
- 画像の差分削除：編集で除外された（新しい画像URL一覧に含まれなくなった）画像のみ、更新成功後にS3から削除する（差し替えていない画像のS3実体は残る。Phase 6-Aで対応済み）。削除直前に他の投稿・アバターからまだ参照されていないかを確認し、参照が残っている場合（旅行プランからの画像引き継ぎ等で同一URLを共有しているケース）は削除しない
- 同時編集の競合対策（楽観ロック、Phase 6-Aで追加）：編集フォームは表示時点の投稿の`version`をPUTリクエストに含める。サーバー側の`version`と一致しない場合（他のリクエストが先に更新済み）は`409 Conflict`を返し、更新自体を拒否する。フロントエンドは「他の画面で更新されています。再読み込みしてください。」とエラー表示する（入力内容は保持されない、既知の制限）。**2026-07-30更新（GATE-04）**：当初は`updatedAt`を競合トークンに使っていたが、いいね・コメント等の非正規化カウンタ更新でも`updatedAt`が進んでしまい、無関係な操作だけで誤って409になる問題があったため、専用の`version`列（投稿本体の更新時のみ進む）に切り替えた

### 3.5 投稿削除

- 本人のみ削除可能
- 削除時、DB上の投稿・PostImageレコードはカスケード削除される。紐づく画像のS3オブジェクトも、他の投稿・アバターからまだ参照されていないことを確認した上で、DB削除成功後にベストエフォートで削除する（Phase 6-Aで対応済み。削除失敗時もリクエスト自体は失敗させない）
- 削除確認ダイアログを表示してから実行する

### 3.6 投稿の編集・削除ボタンの表示

- 自分の投稿カードには、どの一覧画面（ホーム・行きたい・フォロー中の投稿等）でもホバー時に ✏️（編集）・🗑️（削除）ボタンを表示する

## 4. 使用 API

| Method | エンドポイント | 説明 | 認証 |
|--------|--------------|------|------|
| GET | `/api/posts` | フォロー中フィード取得 | 必要 |
| GET | `/api/posts/explore` | 探索ページ用全体フィード取得 | 不要 |
| GET | `/api/posts/portal` | ホーム画面用ポータルフィード取得（人気/新着/エリア/カテゴリ/トップ評価） | 不要 |
| POST | `/api/posts` | 投稿作成（レスポンスは投稿オブジェクト全体） | 必要 |
| GET | `/api/posts/[id]` | 投稿詳細取得 | 不要 |
| PUT | `/api/posts/[id]` | 投稿編集（`version`必須。不一致時は409。2026-07-30更新） | 必要（本人のみ） |
| DELETE | `/api/posts/[id]` | 投稿削除 | 必要（本人のみ） |
| POST | `/api/upload/post` | 写真をS3にアップロード（`uploads/{ownerUserId}/{uuid}.{ext}`） | 必要 |

## 5. バリデーション仕様

フロントエンドは `react-hook-form` + `zod` によるインラインエラー表示（フィールドごとに入力欄の下に日本語エラーを表示）。APIエラーはトーストで表示。

| 項目 | フロントエンド | バックエンド |
|------|-------------|------------|
| スポット名（title） | 必須・1〜40文字・文字数カウンター表示 | 必須・1〜40文字 |
| 感想（body） | 必須・1〜2000文字・文字数カウンター表示 | 必須・1〜2000文字 |
| エリア（location） | 必須・47都道府県から選択 | 必須 |
| カテゴリ（category） | 必須・選択肢から選ぶ | 必須・許可値のみ受け付ける |
| 評価（rating） | 任意・1〜5 の整数 | 任意・1〜5 の整数のみ受け付ける |
| 訪問日（visitedAt） | **必須**・日付形式 | 必須・ISO 日付文字列 |
| 費用内訳（costBreakdown） | 任意・金額 > 0 またはラベルが入力済みの項目のみ保存 | 任意・配列形式 |
| 写真（imageUrls） | 任意・フォーマットチェック・20枚到達時はアップロードをブロック | 任意・MIME タイプ・サイズ検証（アップロード時）、最大20件・1件500文字まで・自分のS3オブジェクトまたは更新前から設定済みのURLのみ（投稿保存時） |

---

## 6. 制約・前提条件

- 写真の最大サイズは1枚あたり10MB、最大枚数は20枚（3.1節参照）
- 地図機能（緯度/経度）との連携は地図機能定義書を参照
- 投稿はログインユーザーのみ作成・編集・削除できる
